# 가상 송신자 데이터로 벤치 시험하기

송신측 GPS·기압계·E22가 아직 없을 때도 실제 BNO085와 DYNAMIXEL을 사용해
전체 지향 동작을 시험할 수 있다. 기존 센서, LoRa, 수학 및 모터 코어는
그대로 두고 `TrackerApp`이 사용할 입력 데이터만 런타임에 선택한다.

## 1. 시뮬레이션 모드

USB 시리얼 모니터를 115200 bps로 열고 다음 명령을 전송한다.

| 명령 | 모드 | 필요한 실제 장치 |
|---|---|---|
| `S0` | 시뮬레이션 OFF, 실제 E22 수신 사용 | 전체 실제 장치 |
| `S1` | 가상 송신자 + 실제 로컬 GPS/BMP581 | BNO085, MAX-M10S, BMP581, DXL |
| `S2` | 가상 송신자 + 가상 로컬 GPS/기압 | BNO085, DXL |
| `SR` | 현재 데이터셋을 처음부터 재시작 | 현재 선택 모드에 따름 |

시뮬레이션은 부팅 시 자동으로 켜지지 않는다. 기본값은 `S0`, 즉 원래의
E22 입력 모드다.

### S1: 실제 로컬 센서 기준

`S1`은 MAX-M10S가 측정한 실제 위도·경도와 BMP581의 실제 기압을 기준으로
가상 송신자 위치를 만든다.

```text
실제 MAX-M10S ─┐
실제 BMP581 ───┼→ 가상 송신자 절대 GPS·기압 생성
가상 궤적 ─────┘
```

실외에서 GPS fix가 잡혀 있고 BMP581도 정상일 때 사용한다. 실제 로컬
GPS 또는 기압이 유효하지 않으면 가상 원격 패킷도 유효해지지 않으므로
짐벌은 추적을 시작하지 않는다.

### S2: 실내 전체 벤치 모드

`S2`는 다음 로컬 기준값을 사용한다.

```text
위도       37.5000000°
경도       127.0000000°
기압       101325 Pa
온도       25°C
GPS fix    3D, 위성 12개
```

따라서 GPS 안테나가 실내에 있거나 BMP581이 아직 연결되지 않았어도
BNO085와 DYNAMIXEL만 정상이면 추적 경로를 시험할 수 있다.

S2에서도 다음 부분은 실제 하드웨어다.

- BNO085 자세
- NED-to-Body 자세 변환
- 목표 yaw/pitch 계산
- 각도 clamp와 속도 제한
- DYNAMIXEL 명령과 피드백
- SD 카드 기록

## 2. 내장 데이터셋

사람이 읽을 수 있는 데이터는
[`data/virtual_target_dataset.csv`](data/virtual_target_dataset.csv)에 있다.
펌웨어가 사용하는 동일 값은
`src/simulation/virtual_target_dataset.h`에 정의되어 있다.

각 행의 의미는 다음과 같다.

```text
time_ms,north_m,east_m,up_m
```

- `north_m`: 로컬 시스템에서 북쪽으로 떨어진 거리
- `east_m`: 로컬 시스템에서 동쪽으로 떨어진 거리
- `up_m`: 로컬 시스템보다 높은 거리

현재 데이터셋은 반경 약 150m의 궤적을 40초 동안 한 바퀴 돈다.

```text
        N
        ● 시작/종료 (150, 0, 0)
     ↗     ↘
 W ●         ● E
     ↖     ↙
        ●
        S
```

고도는 이동 중 `+20m`에서 `-20m` 사이로 변한다. 키프레임 사이는
선형 보간되므로 짐벌 명령이 계단식으로 갑자기 바뀌지 않는다. 40초가
끝나면 처음부터 반복한다.

## 3. 가상 패킷이 들어가는 경로

가상 소스가 추적 결과를 직접 만들지는 않는다. 실제 송신측과 같은
`remote_protocol::Payload`를 생성하고 다음 경로를 거친다.

```text
가상 N/E/고도 키프레임
        ↓
가상 위도·경도·기압 계산
        ↓
34바이트 RK 패킷 encode + CRC16
        ↓
동일한 패킷 Parser로 decode
        ↓
RemoteTargetSample
        ↓
기존 target_geometry
        ↓
기존 DYNAMIXEL 제어
```

따라서 가상 모드에서도 패킷 인코딩, CRC, 디코딩 이후의 추적 파이프라인을
함께 시험한다. UART 전기 신호와 E22 무선 구간만 우회한다.

## 4. 권장 시험 순서

짐벌이 갑자기 움직일 수 있으므로 처음에는 모터 토크를 끄거나 기구를
안전하게 고정한다.

모터가 한 개만 연결된 벤치 구성도 허용한다. ID 1 모터만 응답하면 Yaw
명령만 실제로 구동하고, ID 2 모터만 응답하면 Pitch 명령만 구동한다.
부팅 로그의 `yaw=1/0`, `pitch=1/0`으로 인식된 축을 확인한다. 두 축을
반드시 요구하려면 `system_config.h`의 `REQUIRE_BOTH_DXL`을 `true`로
변경한다.

1. OpenRB, BNO085, DYNAMIXEL, 선택적으로 SD를 연결한다.
2. 펌웨어를 업로드하고 시리얼 모니터를 115200 bps로 연다.
3. `T0`로 토크를 끈다.
4. `S2`를 입력한다.
5. 1초 상태 출력에서 `sim=2`, `imu=1`, `gps=1`, `baro=1`,
   `remote=1`인지 확인한다.
6. 출력되는 `cmd=yaw,pitch`가 시간에 따라 변하는지 확인한다.
7. 기구 주변이 안전하면 `T1`로 토크를 켠다.
8. 실제 짐벌이 40초 동안 가상 송신자 방향을 따라가는지 확인한다.
9. BNO085가 장착된 베이스를 손으로 회전시켜도 지상 기준 방향이
   보상되는지 확인한다.
10. 시험 후 `Z`로 STOW하거나 `S0`로 실제 E22 입력으로 복귀한다.

데이터셋을 처음부터 다시 보고 싶으면 `SR`을 입력한다.

## 5. 상태 출력 예

```text
# mode=1 imu=1 baro=1 gps=1 remote=1 sim=2 range_m=150.0
# cmd=0.0,0.0 rx_ok/bad/lost=10/0/0 sd_rows/errors=25/0
```

- `mode=1`: TRACK
- `sim=1`: 실제 로컬 센서 + 가상 송신자
- `sim=2`: 로컬 GPS/기압과 송신자 모두 가상
- `rx_ok`: 가상 패킷이 정상적으로 encode/decode된 누적 수
- `rx_bad`: CRC 또는 패킷 형식 오류 수

## 6. 실제 E22로 돌아가기

```text
S0
```

이 명령을 보내면 가상 데이터를 즉시 선택 해제하고 원래 E22 수신 샘플을
사용한다. 실제 E22 데이터가 아직 없으면 마지막 방향 유지 또는 STOW
상태로 전환된다.

## 7. 데이터셋 변경

현재 펌웨어는 컴파일된 키프레임 배열을 사용하므로 실제 동작 경로를
바꾸려면 `src/simulation/virtual_target_dataset.h`의 배열을 변경하고
다시 업로드해야 한다.

첫 키프레임과 마지막 키프레임의 위치를 동일하게 두면 루프 경계에서
목표각이 튀지 않는다. `data/virtual_target_dataset.csv`는 문서 및 분석용
복사본이므로 헤더 배열을 바꿀 때 CSV도 함께 맞춰야 한다.
